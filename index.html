Dynamic Programming & DAA Architecture

1. Optimal Substructure & Overlapping Subproblems

In standard game-tree searches, identical board layouts (transpositions) are reached through different move orderings. Without Dynamic Programming memoization, Minimax scales exponentially at O(b^d). By caching solved subproblems in a Transposition Table, we achieve instantaneous O(1) subtree evaluations.

2. 64-Bit Zobrist State Hashing

Board states are mapped to 64-bit integer keys using precomputed pseudo-random bitstrings for each square, piece type, active turn, and polarity inversion state. Updates are performed in O(1) time via incremental XOR (^) bitwise operations on moves and captures.

3. Transposition Table Memoization & Bound Flags

Cached entries store:
• FLAG_EXACT: Precise Minimax evaluation (α < score < β).
• FLAG_LOWERBOUND: Beta cutoff (score ≥ β).
• FLAG_UPPERBOUND: Alpha cutoff (score ≤ α).
• Best Move: Reused in subsequent iterations for Move Ordering, driving Alpha-Beta pruning near optimal O(b^(d/2)) complexity.

4. Quantum Polarity Shift Mechanics

Each player can activate "Polarity Shift" once per game, inverting the board's directional vector 180° for all standard pieces and dynamically swapping King promotion ranks.
